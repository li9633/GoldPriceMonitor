# 日志规范

> 制定日期：2026-10-07。适用于 backend 全部模块；本文是代码评审中日志相关改动的依据。

## 等级语义

| 等级 | 语义 | 判定标准 | 典型例子 |
|---|---|---|---|
| **ERROR** | 需要人工关注 | 数据丢失 / 功能不可用 / 未预期异常。**会被自动重试恢复的不算** | 主循环未捕获异常、DB 写入失败、全部数据源不可用、通知全渠道失败 |
| **WARNING** | 自动恢复，但值得注意 | 发生了降级、跳过、重试、异常数据被丢弃 | 数据源切换、日历降级为星期规则、闸门抑制首条、解析失败跳过某条记录、投递单渠道失败 |
| **INFO** | 业务里程碑 | 事后排查时希望看到的关键节点：启动、配置变更、建议产出、投递结果、定时任务执行结果 | 启动配置、建议落库（advice_id）、通知投递结果（渠道+耗时）、回填统计、每 N tick 运行统计 |
| **DEBUG** | 诊断细节 | 热路径（每 tick / 每请求）的常规输出、中间值、重复出现的同类抑制 | 每 tick 抓到的价格、冷却中跳过某模型、prompt 内容、渠道尝试顺序 |

两条铁律：

1. **热路径禁止 INFO**：每 10 秒 tick 的常规输出（抓价成功、保存成功）必须是 DEBUG。
   一个正常运行的系统在无事件时**不应产生任何 INFO**。
2. **ERROR 不自动恢复**：如果下个 tick 会自动重试且大概率成功，最多 WARNING。

## 格式约定

- **不手写时间戳**：`logger` 已带时间，禁止 `f"[{now()}] ..."`。
- **机器字段用 `key=value`**：`symbol=gds_AUTD price=906.80 advice_id=12`，值不加引号；
  一条日志一个事件，参数用括号或 key=value 追加，不拆成多条。
- **句子式主语在前**：`建议已投递 advice_id=12 action=BUY_PARTIAL price=906.80 model=zhipu/glm-4.7-flash`。
- **禁用横幅**：`========== xxx ==========` 一律取消，用单条结构化日志代替。
- 异常必须带 `exc_info=exc`（或用 `logger.exception`），不能只打 `str(e)`。

## 模块速查（本次优化后的基线）

| 模块 | 热路径输出 | 里程碑 INFO |
|---|---|---|
| monitor_service | 每 tick 价格 → DEBUG | 启动配置、投递结果、回填统计、每 100 tick 统计（单条） |
| price_service | 抓价成功 → DEBUG | 无 |
| model_pool | 模型选择尝试 → INFO（每次 AI 调用一次，非 tick 级） | L4 降级、冷却触发（WARNING） |
| notification_service | 渠道尝试顺序 → DEBUG | 投递结果单条汇总（含各渠道结果） |
| providers/price | 抓价成功 → DEBUG | 数据源切换（WARNING） |
